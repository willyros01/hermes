HERMES 0.6 / FIDUNIO 0.6 — FIREBASE IMPLEMENTATION GUIDE
============================================================

PURPOSE
This release adds the Firebase foundation and the first real one-to-one, two-account Firestore message transport.
The approved FIDUNIO UX and the 0.5 encrypted local IndexedDB Outbox remain in place.

VERY IMPORTANT SECURITY LIMITATION
FIDUNIO 0.6 is a transport test. Cloud message text is NOT end-to-end encrypted yet.
Use only harmless test messages such as "Test 1", "Hello from iPad", etc.
Do not use private, confidential, financial, medical, password, or other sensitive content.
End-to-end encryption/device-key work is a later milestone.

FILES ADDED IN 0.6
- firebase-config.js
- firebase.js
- firestore.rules
- hermes-ux-0.6-setup.txt
- hermes-ux-0.6-memory.txt
All files remain in the repository root.

PART 1 — UPLOAD 0.6 TO GITHUB FROM YOUR IPAD
1. Download hermes-ux-0.6.zip from ChatGPT.
2. In the iPad Files app, tap the ZIP once to expand it.
3. Open the expanded hermes-ux-0.6 folder.
4. Open Safari and go to your existing GitHub repository named: hermes
5. Make sure you are on the main branch.
6. Use Add file -> Upload files.
7. Select all of the files inside the expanded 0.6 folder.
8. Upload them into the ROOT of the hermes repository. Do not create a subfolder.
9. Commit directly to main with a message such as:
   FIDUNIO 0.6 Firebase foundation
10. Wait for GitHub Pages to finish publishing before testing.

PART 2 — CREATE OR SELECT THE FIREBASE PROJECT
Use the Firebase Console, not the Google Cloud credential screen.

1. In Safari open:
   https://console.firebase.google.com/
2. Sign in to the Google account you use for development.
3. Choose one of these:
   A. Create a new Firebase project for FIDUNIO; or
   B. Add Firebase to an existing Google Cloud project if you intentionally want to reuse one.
4. For a clean messaging project, a dedicated Firebase project is recommended.
5. Suggested project display name:
   Fidunio
6. Google Analytics is optional for this stage. You may leave it disabled.
7. Finish creating the project.

PART 3 — REGISTER FIDUNIO AS A WEB APP
1. From Firebase Project Overview, tap the Web icon: </> .
2. App nickname:
   FIDUNIO Web
3. Do NOT enable Firebase Hosting. GitHub Pages is already hosting the PWA.
4. Tap Register app.
5. Firebase displays a configuration object similar to:
   const firebaseConfig = {
     apiKey: "...",
     authDomain: "...",
     projectId: "...",
     storageBucket: "...",
     messagingSenderId: "...",
     appId: "..."
   };
6. Keep this Firebase page open or copy the values to a temporary iPad Note.

IMPORTANT:
These Firebase Web configuration values are client configuration, not a service-account private key.
Do NOT upload service-account JSON/private keys to GitHub.

PART 4 — PUT THE FIREBASE WEB CONFIG INTO firebase-config.js
1. In GitHub, open firebase-config.js.
2. Tap the pencil/edit control.
3. Replace only the placeholder strings with the values Firebase supplied.
4. The result should look like:
   export const firebaseConfig = {
     apiKey: "YOUR_REAL_VALUE",
     authDomain: "YOUR_REAL_VALUE",
     projectId: "YOUR_REAL_VALUE",
     storageBucket: "YOUR_REAL_VALUE",
     messagingSenderId: "YOUR_REAL_VALUE",
     appId: "YOUR_REAL_VALUE"
   };
5. Do not change the property names.
6. Commit the change.

PART 5 — ENABLE EMAIL/PASSWORD AUTHENTICATION
1. Return to Firebase Console.
2. Open Build/Security -> Authentication.
3. If prompted, tap Get started.
4. Open Sign-in method.
5. Select Email/Password.
6. Enable the first Email/Password option.
7. Save.
8. Do not enable phone/SMS authentication for this test.

PART 6 — CREATE CLOUD FIRESTORE
1. In Firebase Console open Build -> Firestore Database.
2. Tap Create database.
3. Choose the production/locked mode option if Firebase asks.
   We will install our own rules immediately afterward.
4. Choose a Firestore location reasonably close to the users you expect.
   IMPORTANT: Firebase resource location can be difficult or impossible to change later.
5. Create the database.

PART 7 — INSTALL THE PROVIDED FIRESTORE SECURITY RULES
Do this BEFORE sending real test traffic.

1. In your GitHub 0.6 files, open firestore.rules.
2. Select and copy the complete contents.
3. Return to Firebase Console -> Firestore Database -> Rules.
4. Replace the existing rules with the contents of firestore.rules.
5. Tap Publish.
6. Confirm the rules publish successfully.

What these 0.6 rules do:
- A user must be authenticated.
- A user can create/update their own user profile.
- Direct conversations must contain exactly two member UIDs.
- Only conversation members may read a conversation.
- Only conversation members may read/send messages in it.
- A sender UID must match the authenticated user.
- Message text is limited to 10,000 characters.
- Conversation membership/type cannot be changed by the 0.6 client.
- Deletes are denied.
- Message updates are limited to receipt-state changes.

PART 8 — ADD YOUR GITHUB PAGES DOMAIN TO AUTHORIZED DOMAINS IF NEEDED
Firebase Authentication normally has localhost and Firebase domains authorized.
For GitHub Pages, verify your site domain is authorized.

1. Firebase Console -> Authentication -> Settings.
2. Find Authorized domains.
3. Add your GitHub Pages host if it is not already listed.
   For a project page, add the HOST only, for example:
   willyros01.github.io
   Do NOT enter /hermes/ in this field.
4. Save.

PART 9 — WAIT FOR GITHUB PAGES / SERVICE WORKER UPDATE
Because FIDUNIO is a PWA, an older service worker can briefly keep an older release.

1. Wait for the GitHub Pages deployment to complete.
2. Open your FIDUNIO GitHub Pages site.
3. Verify Settings -> About says Version 0.6.
4. If it still says 0.5:
   - close the FIDUNIO tab/PWA,
   - reopen it while online,
   - refresh once,
   - then check Version again.
5. Do not begin Firebase testing until the screen clearly says 0.6.

PART 10 — CREATE TEST ACCOUNT A ON THE IPAD
1. Open FIDUNIO 0.6 on the iPad.
2. Unlock the prototype.
3. Open Settings.
4. Find Firebase Account.
5. Enter:
   - Display name: a harmless test display name
   - Email: test account A
   - Password: a test password meeting Firebase requirements
6. Tap Create Test Account.
7. Once signed in, FIDUNIO shows:
   Your FIDUNIO ID
   followed by a long Firebase UID.
8. Tap Copy FIDUNIO ID.
9. Save this UID temporarily in Notes.

PART 11 — CREATE TEST ACCOUNT B ON THE IPHONE
You need a different Firebase account on the second device.

1. Open FIDUNIO 0.6 on the iPhone.
2. Go to Settings -> Firebase Account.
3. Create test account B with a different email address.
4. When it signs in, copy account B's FIDUNIO ID.
5. Keep both UIDs temporarily.

PART 12 — CREATE THE FIRST REAL CLOUD CONVERSATION
Example: start from the iPad/account A.

1. On iPad, return to Messages.
2. Tap + for New Message.
3. Find:
   FIDUNIO ID — 0.6 test
4. Paste the iPhone/account B UID.
5. Tap Start Cloud Conversation.
6. FIDUNIO should open a direct conversation with account B's display name.
7. A warning will appear reminding you that 0.6 is not E2EE yet.

PART 13 — SEND THE FIRST REAL TWO-DEVICE MESSAGE
1. Keep both devices online.
2. On iPad/account A send:
   Test from iPad
3. The message is written to Cloud Firestore.
4. On iPhone/account B, the cloud conversation should appear in Messages.
5. Open it.
6. You should see the iPad test message.
7. Reply from iPhone:
   Test from iPhone
8. The reply should appear on the iPad.

At this point, two-device Firestore transport is working.

PART 14 — TEST THE REAL OFFLINE OUTBOX WITH FIREBASE
1. Keep account A and B signed in.
2. On iPad, open the cloud conversation.
3. Put the iPad in Airplane Mode.
4. Send:
   Offline cloud test
5. It should show Queued.
6. Leave the message queued for a few seconds.
7. Optional stronger test:
   close/reopen FIDUNIO while still offline and confirm the queued item survives.
8. Turn Airplane Mode off.
9. Reopen/foreground FIDUNIO if necessary.
10. The 0.5 IndexedDB Outbox should attempt the Firestore send.
11. Verify the message appears on the iPhone.

PWA LIMITATION:
iOS may suspend the PWA. FIDUNIO cannot guarantee that a queued message leaves at the exact instant the connection returns while the app is suspended. Foregrounding the PWA gives it execution time and should trigger retry.

PART 15 — VERIFY FIRESTORE DATA
In Firebase Console -> Firestore Database -> Data you should see:
- users
- conversations

Inside a direct conversation document:
- members: two Firebase UIDs
- memberNames
- type: direct
- timestamps

Inside:
conversations/{conversationId}/messages
you should see the harmless test messages.

Again: 0.6 messages are plaintext transport-test data in Firestore. This is why only harmless test messages should be used.

PART 16 — EXPECTED 0.6 PASS CRITERIA
Consider 0.6 successful only if all of these pass:
1. FIDUNIO visibly reports Version 0.6.
2. Existing iPhone/iPad group overflow remains fixed.
3. A/A+/A++ still work.
4. Auto/Light/Dark still work.
5. History Access controls still work.
6. Two separate Firebase email/password accounts can sign in.
7. Each account has a FIDUNIO ID/UID.
8. Account A can create a direct conversation by entering account B's UID.
9. Online message A -> B appears on device B.
10. Online reply B -> A appears on device A.
11. Airplane-mode cloud message shows Queued.
12. Queued cloud message persists across reload/reopen.
13. After reconnection/foreground, queued cloud message reaches the other device.
14. No Firebase "permission denied" errors appear.

TROUBLESHOOTING
A. Settings says "Not configured"
- firebase-config.js still contains one or more PASTE_ placeholder values.
- Recheck all six Firebase fields and commit the change.

B. auth/unauthorized-domain
- Add your GitHub Pages HOST under Authentication -> Settings -> Authorized domains.
- Example host only: willyros01.github.io

C. Missing or insufficient permissions
- Firestore rules are not published, or the wrong project/config is being used.
- Republish firestore.rules.
- Verify firebase-config.js projectId matches the Firebase project where you published the rules.

D. Recipient FIDUNIO ID was not found
- Re-copy the other account's UID exactly.
- Confirm that the other account successfully created/signed in and therefore has a users/{uid} profile.

E. Firebase module fails to load
- Make sure the device is online for the initial Firebase SDK load.
- This build uses Firebase's official browser-module CDN.
- Reload after restoring internet.

F. 0.5 still appears after upload
- GitHub Pages or the old PWA service worker is still serving the previous cache.
- Wait for deployment, reopen online, and refresh.
- Confirm About says 0.6 before testing.

G. Message stays Failed after reconnection
- Open Settings and look for the Firebase error message.
- Check that the user is still signed in.
- Check Firestore Rules and internet connectivity.
- Reopen the PWA to give iOS execution time.

WHAT IS NOT PART OF 0.6
- End-to-end encryption
- Device identity keys
- Key verification
- Multi-device key management
- Production group encryption/key rotation
- Push notifications
- Passkey/WebAuthn enforcement
- Attachments
- App Check hardening
- Production user discovery/contact exchange

NEXT MILESTONE AFTER 0.6 PASSES
0.7 should focus on encryption/device identity before FIDUNIO is used for anything beyond harmless transport testing.
