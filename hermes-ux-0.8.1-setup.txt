HERMES 0.8.1 / FIDUNIO 0.8.1 — KEY VERIFICATION + KEY-CHANGE DETECTION

PURPOSE
0.8.1 builds on the fully passed 0.8.0 device-identity foundation without changing the stable 0.7.3 transport, local-first history, Outbox, reconnect behavior, or direct-message ciphertext format.

WHAT IS NEW
- FIDUNIO records the first observed contact encryption-key fingerprint locally inside encrypted app state.
- Conversation Info (ⓘ) for a cloud direct chat now opens Conversation Security.
- Conversation Security shows the contact's current public-key fingerprint and registered-device count.
- "Verify Current Key" lets you mark the fingerprint verified on that installation after comparing it with your contact using a trusted separate channel.
- If a previously verified key later changes, FIDUNIO displays a security warning and pauses NEW outgoing messages to that contact until the new fingerprint is reviewed and explicitly verified.
- If an unverified key changes, FIDUNIO warns but does not claim it was previously trusted.
- The peer key is refreshed during live receive/send, rather than being trusted indefinitely from an in-memory cache.

IMPORTANT
Verification in 0.8.1 is LOCAL TO EACH INSTALLATION. It is not yet QR linking, automatic device approval, or full multi-device recipient encryption.

KEY-CHANGE TEST
Do NOT clear site data or force a key change just to test this. A real key change can be tested later in a controlled disposable-account scenario. 0.8.1 is designed to warn and pause new sends after a previously verified fingerprint changes.

SECURITY STATUS
Still not production-grade Signal-equivalent messaging. Missing: automatic verified device linking/QR approval, true per-device recipient envelopes, forward secrecy/Double Ratchet, group E2EE, and stronger contact authorization.
