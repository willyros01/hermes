HERMES 0.6.5 / FIDUNIO 0.6.5 — UPDATE AND RETEST
=======================================================

WHY 0.6.5
0.6.4 still lost visible cloud history after:
Airplane Mode -> kill FIDUNIO -> reopen offline.

A comparison with the user's proven JavaScript Scorecard app exposed the better rule:
LOCAL DURABLE DATA FIRST; FIREBASE SYNCHRONIZATION SECOND.

A concrete FIDUNIO bug was then identified:
an offline Firestore cache snapshot can be empty. Earlier FIDUNIO code replaced the
locally restored message array with that empty snapshot. This made downloaded history
appear to vanish offline, then reappear as soon as a real server snapshot arrived.

0.6.5 does not allow an offline/cache snapshot to erase local history.

IMPORTANT CONFIGURATION
The ZIP intentionally omits:
- firebase-config.js
- config-firestore.js

Keep the configured copies already in the hermes GitHub repository.
Do not delete, replace, or rename them.

UPLOAD FROM IPAD
1. Expand hermes-ux-0.6.5.zip.
2. Upload ALL included files to the ROOT of the existing hermes repository.
3. Commit.
4. Do not remove firebase-config.js because it is absent from the ZIP.
5. Wait for GitHub Pages deployment.
6. Open FIDUNIO online on iPad and iPhone.
7. Confirm Settings -> About shows Version 0.6.5 on both.

IMPORTANT FIRST LAUNCH
Because 0.6.5 installs a different service-worker strategy, do the first 0.6.5
launch while ONLINE on both devices. Leave FIDUNIO open for several seconds so the
new worker and Firebase SDK cache can settle.

NO FIREBASE CONSOLE CHANGES ARE REQUIRED.

TEST 1 — ONLINE LIVE MESSAGING
1. Open the existing cloud conversation on both devices.
2. iPad sends:
   Live 0.6.5 from iPad
3. PASS: it appears on iPhone without killing/reopening.
4. iPhone replies:
   Live 0.6.5 from iPhone
5. PASS: it appears on iPad without killing/reopening.
6. Leave both new messages visible on iPad for about 5 seconds.

TEST 2 — OFFLINE HISTORY COLD START
1. On iPad turn Airplane Mode ON.
2. Kill/close FIDUNIO.
3. Reopen FIDUNIO while still offline.
4. Open the same cloud conversation.
PASS: Live 0.6.5 from iPad and Live 0.6.5 from iPhone are still visible.

If TEST 2 fails, STOP there and report it.
Do not proceed to the Outbox test.

TEST 3 — OUTBOX SURVIVAL
Only if TEST 2 passes:
1. Keep Airplane Mode ON.
2. Send:
   Offline queued 0.6.5
3. Confirm it shows Queued.
4. Kill FIDUNIO while still offline.
5. Reopen while still offline.
6. Open the conversation.
PASS: Offline queued 0.6.5 is still present.

TEST 4 — RECONNECT DELIVERY
1. Restore communications.
2. Foreground FIDUNIO if needed.
3. Keep iPhone online.
PASS: Offline queued 0.6.5 reaches iPhone.
PASS: it remains visible on iPad.
PASS: status may advance after recipient/server processing.

WHAT CHANGED IN THE SERVICE WORKER
- FIDUNIO files: network-first, cache fallback.
- Firebase SDK JavaScript on www.gstatic.com: cached.
- Firebase data/API traffic: never service-worker cached.

SECURITY
0.6.5 still stores cloud message text in Firestore without E2EE.
Use harmless test messages only.
