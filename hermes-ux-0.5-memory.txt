GROUP MESSAGING RULES
- Group creation: New Message -> New Group -> select members -> group name -> create.
- Group Info includes members, add/remove, rename, mute, search, shared media/files, disappearing/security options, leave group.
- Creator starts as Owner/Admin.
- New members do NOT automatically receive old group history.
- Admin may explicitly grant prior history (examples: last 24h, last 7d, selected date, entire available history).
- Production enforcement must eventually be cryptographic with group-key rotation on membership changes.

ARCHITECTURE DIRECTION
- HTML/CSS/JavaScript PWA.
- Firebase Authentication + Firestore + Cloud Storage + Cloud Functions later.
- FCM where supported; do not depend on FCM alone for Fire OS.
- App Check + Firestore/Storage Security Rules.
- Web Crypto API / vetted crypto only; never custom crypto.
- WebAuthn/passkeys for biometric-style unlock; PIN/password fallback.
- IndexedDB local storage and Outbox.
- Message states: Queued -> Sending -> Sent -> Delivered -> Read; Failed when needed.
- Client-generated unique IDs/idempotency to avoid duplicates.
- Push notifications should not contain plaintext message content by default.
- PWA limitation accepted: background sending cannot be guaranteed while iOS/browser suspends the app.

CURRENT RELEASE: 0.5
This is the first functional local build.

Implemented in 0.5:
- Responsive group-layout fix intended to eliminate horizontal page scrolling on iPhone/iPad.
- Added service-worker.js.
- Added app-shell caching for PWA/offline foundation.
- Added IndexedDB persistence for conversations, messages, settings, quick phrases, and selected conversation.
- Local persisted state is encrypted using AES-GCM via Web Crypto.
- Added persistent IndexedDB Outbox.
- Offline messages use client-generated UUIDs and remain queued across reload/relaunch.
- When connectivity returns and the PWA gets execution time, queued messages are processed and simulated through Sending/Sent/Delivered/Read states.
- Preserved approved FIDUNIO branding and graphics.
- Preserved A/A+/A++ text sizing.
- Preserved History Access modal fixes.
- Preserved flat repository layout.

IMPORTANT 0.5 LIMITATIONS
- Firebase is NOT connected yet.
- Two-device messaging is NOT implemented yet.
- Current message delivery progression after reconnect is simulated locally.
- Current local AES-GCM persistence is a prototype foundation, not the final E2EE/device-key design.
- Production key wrapping/recovery, multi-device keys, group-key rotation, Firebase transport, Auth, Security Rules, App Check, notifications, and passkeys are still future work.
- PWA background retry cannot be guaranteed while the OS/browser fully suspends the app.
