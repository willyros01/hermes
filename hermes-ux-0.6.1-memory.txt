0.6 OFFLINE TEST RESULTS — FAILED / BUG FOUND
Observed on iPad:
- After killing/reopening FIDUNIO while offline, previously received iPhone messages were not visible.
- When connectivity returned, those remote messages came back from Firestore.
- A queued offline cloud message left no trace after reconnect and did not arrive on iPhone.

ROOT CAUSE ADDRESSED IN 0.6.1
- 0.6 Firestore snapshot replacement could wipe local pending cloud messages.
- 0.6 retry logic depended on a matching message already existing in state.messages.
- If normal local state was missing, it deleted the Outbox record instead of rebuilding the message.
- Critical IndexedDB writes did not wait for transaction completion.
- A startup while online could call flush before Firebase auth restoration, and auth restoration did not itself trigger a retry.
- Cloud downloaded messages were not made durable strongly enough before an offline kill/reopen.

0.6.1 FIXES
- Encrypted IndexedDB Outbox is authoritative.
- Outbox payload includes enough conversation/message data to reconstruct missing queued UI state.
- Startup decrypts and restores Outbox records into state before first render.
- Critical IndexedDB writes wait for transaction completion.
- Incoming Firestore messages are immediately committed to encrypted local cache.
- Firestore snapshots merge/preserve local queued/sending/failed messages.
- Auth restoration triggers Outbox retry when online.
- Outbox record is removed only after successful Firestore write.
- Missing message cache no longer causes Outbox deletion.
- Cloud direct status changed from Secure to Connected until E2EE exists.
