HERMES 0.8.0 / FIDUNIO 0.8.0 — DEVICE IDENTITY FOUNDATION

WHAT 0.8.0 ADDS
- A stable random Device ID for each FIDUNIO installation.
- Reuses the existing non-exportable 0.7.x ECDH P-256 private key; upgrading does NOT intentionally rotate your working E2EE key.
- SHA-256 public-key fingerprint shown in Settings → Device Identity.
- Firestore device registry at users/{uid}/devices/{deviceId}.
- New encrypted messages include senderDeviceId metadata.
- The existing account-level e2eePublicJwk remains as a compatibility bridge, so the proven 0.7.3 direct E2EE transport is preserved.

IMPORTANT LIMITATION
0.8.0 is the MULTI-DEVICE IDENTITY FOUNDATION, not full multi-device message fan-out yet.
A message is still encrypted using the current account-level compatibility key. Do not test one Firebase account simultaneously on multiple new installations yet and assume every device can decrypt the same message. Per-device recipient envelopes are a later milestone.

GITHUB
1. Upload the files from hermes-ux-0.8.0.zip to the ROOT of the existing hermes repository.
2. Do NOT overwrite or delete firebase-config.js or config-firestore.js. Neither is included in this ZIP.
3. Commit and wait for GitHub Pages deployment.
4. In GitHub, open version.js and verify:
   version: "0.8.0"

FIRESTORE RULES — REQUIRED FOR DEVICE REGISTRATION
0.8.0 adds users/{uid}/devices/{deviceId}, so publish the included firestore.rules once before testing the Device Identity registry.
The message/conversation rules remain the same; the new rule block only authorizes authenticated public-device-key reads and owner-only device-key writes.
