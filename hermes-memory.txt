==================================================
0.8.1.10 → 0.8.1.12 — IPAD SENT → READ DEFECT
==================================================

Original defect:
- On iPad two-pane layout, an outgoing message could remain visually at Sent after the iPhone opened/read the conversation.
- Older single-pane/earlier transport behavior had previously passed automatic live receipt.
- Strong suspicion: listener/render lifecycle changed when the persistent two-pane iPad UI was introduced.

0.8.1.10 — FAILED EXPERIMENT
- Added a 2-second server refresh/poll of the active conversation in firebase.js.
- On iPad this caused repeated refreshing and broke normal sending usability.
- This approach is rejected. Do NOT reintroduce periodic active-conversation server polling for receipt refresh.

0.8.1.11 — ROLLBACK / RESTORE
- Removed the polling experiment.
- firebase.js messaging subscription returned to the exact known-good pre-experiment blob.
- Normal sending behavior restored, but Sent → Read still did not update live.

0.8.1.12 — ORDERED MESSAGE-SNAPSHOT FIX — USER PASS
Diagnosis:
- Firestore message snapshots invoke an async app callback that refreshes peer keys and decrypts rows before committing state/render.
- In the persistent iPad two-pane chat, multiple snapshots can arrive close together and async processing can overlap.
- An older Sent snapshot could finish after a newer Read snapshot and overwrite/repaint the UI with stale receipt state.

Fix:
- Kept the existing Firestore onSnapshot design.
- No polling, no timer-driven server refresh and no page refresh loop.
- serialize/queue active-conversation snapshot processing so async snapshot callbacks complete strictly in arrival order.
- Preserve the existing 0.7.3 active-listener lifecycle and iPad two-pane UI.
- No E2EE format, device identity, Outbox, local-history or Firestore Rules change required.
- Service worker was touched for the v12 shell so iOS installs the correct versioned assets.

USER TEST RESULT — PASS:
- v0.8.1.12 displayed on iPad.
- iPad could send normally.
- Message read on iPhone updated automatically from Sent → Read on the iPad.
- User explicitly reported: “it works!”

Treat FIDUNIO 0.8.1.12 as the current validated pre-0.9.0 rollback baseline.
Preserve this ordered listener behavior during 0.9.0 E2EE work.
