0.9.0 LIVE TEST STATUS
- release/0.9.0 was intentionally fast-forward promoted to main after Firestore rules were published.
- Test at the normal GitHub Pages root only; do not use a separate Pages subdirectory/origin so established browser storage/key context is preserved.
- Firestore rules accept bounded e2ee:2 envelope messages while retaining e2ee:1 compatibility.
- firebase.js transport carries envelopes, recipientDeviceIds, senderDeviceId, and senderDevicePublicJwk.
- 0.9.0 test service-worker harness injects per-device E2EE into baseline app.js for this controlled test: it reads active registered devices for both recipient and sender accounts, creates a separate AES-256-GCM ciphertext envelope per device using P-256 ECDH + HKDF, and includes the sending device public key for recipient-side derivation.
- e2ee:2 receive path selects only the envelope addressed to this installation and decrypts with its non-exportable local device private key.
- Existing e2ee:1 history retains the old compatibility decrypt path.
- Outbox remains authoritative; device envelopes are generated at actual transmission/retry time from the current registry rather than stored with stale device membership in the queued record.
- Two-device validation: existing history readable PASS; iPad→iPhone plaintext + Read PASS; iPhone→iPad plaintext + Read PASS; leave/send/re-enter Sent→Read PASS on 0.9.0.2.
- Offline Outbox/reconnect validation on 0.9.0.2: PASS in both directions between iPad and iPhone. Queued messages successfully resume transmission after reconnect under the per-device E2EE path.
- Third-device setup: Fire HD 8 signed into the same Beta account as iPhone; Conversation Security on iPad reported 2 registered devices. Fire device fingerprint did not match the displayed account-level compatibility fingerprint, confirming the old verification UI/gate is account-level rather than per-device.
- Fire HD 8 cannot decrypt older messages that lack an envelope for its newly registered device; this is expected for messages created before that device was included in the recipient device set. Preserve this behavior/history for testing.
- 0.9.0.3 FAILED before send: Conversation Security still opened on iPad because the exact service-worker source transform intended to remove the pre-queue legacy trust gate did not match the live app.js source. No test message was transmitted.
- 0.9.0.4 adds a narrowly scoped fallback matching the same pre-send account-level trust block. The Outbox transmit path remains per-device e2ee:2 and does not use the legacy compatibility fingerprint as an authorization gate.
- 0.9.0.4 THIRD-DEVICE FAN-OUT PASS: user sent a new message from iPad after Fire HD 8 registration. Both iPhone and Fire HD 8 independently displayed the new message normally, and the iPad sender status changed to Read. This validates current registered-device fan-out and recipient decryption for two devices on the same Beta account while preserving sender receipt behavior.
