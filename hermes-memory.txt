PIN / BIOMETRIC REDESIGN — AUTHORITATIVE ARCHITECTURE
- The failed 0.9.4.x PIN experiments are rejected and are not a development baseline. Do not reuse their layered overlay/modal architecture.
- Restart PIN/biometric only from validated 0.9.3.7.
- Development branch: pin-biometric-redesign, created directly from validated 0.9.3.7 commit db15b15c92ea476f81a2ccc37e08dde53a2e491e.
- app.js state.unlocked remains the one and only authoritative local LOCKED/UNLOCKED state.
- There must be exactly one FIDUNIO unlock screen and one successful local unlock path. No competing overlays, no browser prompt() PIN entry, no synthetic/simulated unlock-button clicks, and no MutationObserver unlock bridge.
- local-security.js is a helper only: PIN derivation/verification, WebAuthn device authentication, timeout configuration, and inactivity monitoring. It does not own another app-lock state or render a lock overlay.
- Raw PIN is never stored. Store only a PBKDF2-SHA256 verifier with a random per-installation salt. PIN is local to each installation.
- PIN input is an app-owned masked password/numeric field, 4–12 digits, visible correctly in both Light and Dark modes.
- Device unlock uses standards-based WebAuthn with user verification required and platform authenticator where supported. PIN always remains fallback.
- Firebase authentication and local unlock remain separate. Firebase can stay signed in while FIDUNIO UI is locally locked.
- auth-unlock-bridge.js is removed from the redesign startup path. Successful Sign In / successful invitation redemption explicitly marks a one-shot bypass only after authentication succeeds; app.js consumes that bypass once.
- Inactivity choices: Immediately, 1 min, 5 min, 15 min, 30 min, 1 hr, Never; default 5 min. Immediately means lock on background/leave, not a zero-delay foreground loop.
- Lock Now calls the same single lock function as inactivity.
- Do not promote to main or assign a final 0.9.4 release until the complete PIN/biometric acceptance matrix passes. Avoid release-number churn during branch development.
- Acceptance matrix: one startup unlock screen; correct PIN unlock; wrong PIN remains locked; masked dots visible Light/Dark iPhone/iPad; Lock Now first tap; each timeout selectable; Immediately background/return; 1-minute inactivity; WebAuthn enrollment; WebAuthn unlock; cancel/failure gives PIN fallback; restart/refresh while locked; explicit successful Sign In/Join bypass once; Firebase remains signed in; messaging/Read receipts/Outbox/E2EE unchanged.
