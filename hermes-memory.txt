PIN / BIOMETRIC REDESIGN — AUTHORITATIVE ARCHITECTURE
- The failed earlier 0.9.4.x PIN experiments are rejected. Do not reuse layered overlay/modal architecture.
- Current redesign was built cleanly from validated 0.9.3.7.
- app.js state.unlocked is the one authoritative local LOCKED/UNLOCKED state.
- Exactly one FIDUNIO unlock screen and one successful local unlock path. No competing overlays, browser prompt PIN, synthetic unlock clicks, or MutationObserver unlock bridge.
- local-security.js is helper-only: PIN derivation/verification, WebAuthn device authentication, timeout configuration, inactivity monitoring. It does not own another app-lock state or render a lock overlay.
- PIN configuration is persisted in IndexedDB fidunio-local/meta with verification; legacy localStorage config is migrated if present.
- Raw PIN is never stored. Store only PBKDF2-SHA256 verifier with random per-installation salt; 210000 iterations. PIN is local to each installation.
- PIN input is app-owned masked numeric/password field, 4–12 digits.
- Device unlock uses standards-based WebAuthn with user verification required and platform authenticator where supported. PIN remains fallback.
- Firebase authentication and local unlock remain separate. Firebase can stay signed in while FIDUNIO UI is locally locked.
- Successful Sign In / successful invitation redemption marks a one-shot bypass only after authentication succeeds; app.js consumes it once.
- Inactivity choices: Immediately, 1 min, 5 min, 15 min, 30 min, 1 hr, Never; default 5 min. Immediately means lock on background/leave, not zero-delay foreground loop.
- Lock Now calls the same single lock function as inactivity.
