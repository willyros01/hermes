HERMES 0.7.2 / FIDUNIO 0.7.2 — E2EE CONVERSATION REPAIR

PURPOSE
0.7.2 repairs the E2EE peer-identity/conversation restoration defect found in 0.7.1.

WHAT CHANGED
- Cloud conversation merges now preserve peerUid.
- Older cached cloud conversations missing peerUid can repair it from the Firestore conversation document.
- Encrypted Outbox records now preserve peerUid for future cold-start recovery.
- Firestore conversation discovery reattaches the active chat and retries preserved Outbox work after repair.
- Existing accounts, conversation IDs, E2EE device keys, local-first/offline architecture, and Firestore rule design are retained.
- version.js remains the single authoritative version source.

UPLOAD
1. Upload all ZIP files to the ROOT of the existing hermes repository.
2. Do NOT delete or overwrite firebase-config.js or config-firestore.js. They are intentionally excluded.
3. Commit and wait for GitHub Pages deployment.
4. Open version.js in GitHub and verify version: "0.7.2".
5. Do NOT change Firestore rules for this repair; the 0.7.0/0.7.1 E2EE rules may remain published.

REPAIR TEST
1. Keep iPad and iPhone online and signed into their existing accounts.
2. Open/reload FIDUNIO 0.7.2 on both. Do not create a new conversation and do not copy the FIDUNIO ID again.
3. Wait several seconds on Messages. The existing cloud conversation should reappear on the iPhone from Firestore discovery.
4. On iPad, open the existing conversation. The previously failed Outbox message may retry automatically. If it sends, confirm it is readable on iPhone.
5. If needed, send a fresh message from iPad: Encrypted 0.7.2 from iPad
6. Send from iPhone: Encrypted 0.7.2 from iPhone
7. Both must arrive readable. If "[Encrypted message — key unavailable]" appears, stop and report which device.

AFTER TWO-WAY E2EE PASSES
Repeat the existing offline cold-start history and offline Outbox/reconnect tests.

SECURITY
This remains an E2EE foundation. Do not use sensitive/private content yet.
