CRITICAL SECURITY LIMITATION
0.6 cloud message text is NOT end-to-end encrypted yet.
Use harmless test messages only.
Firebase/Firestore can technically see cloud message plaintext in this transport prototype.
Do not use private, confidential, financial, medical, password, or other sensitive content.
0.7 should prioritize E2EE/device identity before expanding real usage.

FIRESTORE RULE DESIGN
- Authentication required.
- Users can create/update their own user profile.
- Authenticated profile reads are allowed in 0.6 to resolve a known UID.
- Direct conversation creation requires exactly two members and requester membership.
- Conversation reads limited to members.
- Membership/type cannot be changed through 0.6 update.
- Message reads limited to conversation members.
- Message create senderUid must equal authenticated UID.
- Text must be 1..10000 chars.
- Message updates limited to state changes delivered/read.
- Deletes denied.

0.6 REQUIRED USER SETUP
See hermes-ux-0.6-setup.txt for full iPad-first instructions.
High-level:
1. Upload all 0.6 files to GitHub hermes repo root.
2. Create/select Firebase project.
3. Register Web app.
4. Paste Web config values into firebase-config.js.
5. Enable Authentication -> Email/Password.
6. Create Firestore database.
7. Publish provided firestore.rules.
8. Add GitHub Pages host to Firebase Auth Authorized domains if needed.
9. Wait for GitHub Pages and confirm About says 0.6.
10. Create account A on iPad and account B on iPhone.
11. Exchange/copy their FIDUNIO IDs (Firebase UIDs).
12. New Message -> FIDUNIO ID -> paste other account UID.
13. Test online A->B and B->A.
14. Test Airplane Mode queued cloud message and reconnect delivery.
